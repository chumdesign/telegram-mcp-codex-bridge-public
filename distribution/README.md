# Передача Codex Telegram Bridge

Комплекты `macos-arm64` и `windows-x64` содержат один и тот же JAR нашего форка,
Java runtime, Python-адаптер общего локального сервиса, навык и `source.zip` с исходниками.
Версия 1.20.0-codex.1 содержит merge upstream v1.20.0 с нашими доработками.
TDLight 3.5.9 / TDLib 1.8.68; MCP SDK 2.1.0. Сравнение альтернатив — в `RESEARCH.md`.
M1 и M4 используют один комплект `macos-arm64`.

## Требования

- macOS 14+ на Apple Silicon (M1/M4) и Python 3.11+ ARM64. Intel Mac пока не поддерживается
  поставляемой TDLight-библиотекой. При запуске Python через Rosetta установите
  ARM64 Python.
- Windows x64, Python 3.11+ и PowerShell 7 по стандартному пути установки.
- Собственное приложение Telegram API и существующий Telegram на телефоне.
- Локальный пользователь с доступом к своему Keychain или Windows DPAPI.

Доступность Rich-публикаций, квоты и права на изменения определяет Telegram.
Проверяйте статьи на аккаунте с Premium и подходящими правами в целевом чате.

API ID/API hash получатель создаёт на https://my.telegram.org/apps.
Пароль 2FA вводится только в локальном мастере входа. Установщик сохраняет API hash
в Keychain на Mac либо в DPAPI-блоке Windows. Сессия TDLib и журналы находятся в
каталоге пользователя с ограниченным доступом. Для защиты сессии при краже диска
используйте FileVault или BitLocker. Шифрование TDLib-сессии отдельным паролем
в этом комплекте не заявляется.

## macOS

Распакуйте `.tar.gz` в постоянную или временную папку. В Terminal выполните
`bash Install.command`. Установщик скопирует комплект в
`~/Library/Application Support/TelegramMcpCodexBridge/app`, запросит API-данные,
добавит отдельную запись `telegram-reader` в Codex с `required = false` и установит
навык `telegram`. При совпадении имени уже существующего MCP запись сохраняется
и установка останавливается до ввода API-данных. Для ручного подключения сначала
выполните `python3 bridge.py setup` без флага регистрации, затем сопоставьте
созданный `generated-codex.toml` с существующей записью.

Затем выполните

```sh
python3 "$HOME/Library/Application Support/TelegramMcpCodexBridge/app/bridge.py" auth
python3 "$HOME/Library/Application Support/TelegramMcpCodexBridge/app/bridge.py" doctor
python3 "$HOME/Library/Application Support/TelegramMcpCodexBridge/app/acceptance.py"
```

Мастер откроет локальную страницу входа. Отсканируйте QR через Telegram на телефоне.
Ввод API ID/hash в мастере может потребоваться повторно. После входа сервис
запускается и совместно используется чатами Codex. Для загрузки каталога команд
перезапустите Codex. При следующем обращении MCP адаптер сам запускает сервис.

## Windows

Распакуйте ZIP. В PowerShell 7 выполните `./Install.ps1`.
Дополнительные каталоги файлов можно указать через
`./Install.ps1 -FileRoot 'D:\Projects','C:\Users\yourname\Documents'`.
Затем выполните

```powershell
python "$env:LOCALAPPDATA\TelegramMcpCodexBridge\app\bridge.py" auth
python "$env:LOCALAPPDATA\TelegramMcpCodexBridge\app\bridge.py" doctor
python "$env:LOCALAPPDATA\TelegramMcpCodexBridge\app\acceptance.py"
```

Если выполнение скачанных скриптов ограничено Windows, проверьте содержимое и
SHA-256 комплекта. После проверки запускайте команды Python напрямую из папки
комплекта: `python bridge.py setup --register-codex`, затем команду `auth`,
которую напечатает установщик. Глобальную execution policy менять не требуется.

## Проверка у получателя

`acceptance.py` проверяет MCP, профиль своего аккаунта и необходимые инструменты.
Ключ `--send-self` отдельно разрешает отправку одного тестового сообщения в
собственное «Избранное». Зафиксируйте результат этой проверки на Mac.
Для визуальной проверки native approval вызовите выбранную опасную операцию и
нажмите «Отмена». Убедитесь, что окно показывает правильный аккаунт и цель.
Самостоятельно нажимать подтверждение агенту запрещено.

## Обслуживание

Команды `bridge.py start`, `stop`, `doctor`, `config` управляют только сервисом
этого комплекта. `auth` требует остановленного сервиса. Порт по умолчанию 17433,
его можно выбрать при установке: `setup --port 17434 --register-codex`.
Повторный setup поверх готовой установки останавливается с понятной ошибкой.
Обновление выполняйте после резервной копии локального каталога и `stop`.

Каталоги для загрузки файлов задаются при setup. По умолчанию доступны Documents,
Downloads/Telegram MCP Files и publish-ready. API hash, ключ MCP, сессия и журналы
создаются на компьютере получателя. Эти файлы в комплект не включаются.

Python-адаптер использует только loopback, отключает прокси и HTTP redirects,
получает ключ из локального файла и создаёт отдельную MCP-сессию каждому чату.
Один файловый замок защищает TDLib от одновременного запуска в нескольких процессах.
После восстановления соединения изменения автоматически не повторяются.

На Mac обязательное подтверждение показывает системный `osascript`-диалог,
на Windows — Windows Forms. При закрытии, отказе или тайм-ауте операция отклоняется.
Повторная отправка после неопределённого результата требует проверки доставки.

## Что проверено при подготовке

Фактические результаты входят в `VERIFICATION.json`. Mac runtime и комплект
проверены по структуре и контрольным суммам. Запуск TDLib и внешний вид диалога
на Mac требуют проверки на машине получателя. Для этого приложен `acceptance.py`.
Готовая подпись Apple Developer и notarization для нашей модифицированной сборки
не заявляются.

## Сборка разработчиком

Распакуйте `source.zip` в короткий путь. Установите JDK 25, затем выполните
`bash ./gradlew test bootJar -PreleaseVersion=1.20.0-codex.1` на Mac
или `./gradlew.bat test bootJar -PreleaseVersion=1.20.0-codex.1` на Windows.
Зависимости загружаются из Maven при первой сборке. Для пересборки комплектов
используйте `scripts/package-codex-bridge.py` с собственным каталогом проверенных
runtime-архивов, JAR, отчётами тестов и навыком. Полный синтаксис доступен через
`python scripts/package-codex-bridge.py --help`.


## Совместимость 1.20.0-codex.1

Сохранены 12 дополнительных инструментов: статьи с настоящими таблицами и обложками,
редактирование изображений без перепубликации, custom emoji, папки и проверяемая
миграция групп. Отправки статей и альбомов поддерживают `idempotency_key`: после
потери ответа проверяйте `get_send_operation` и не повторяйте UNKNOWN автоматически.
Нативное подтверждение запрашивается при опасном вызове, не при MCP initialize.

На настоящем Mac требуется приёмочная проверка, описанная выше; структурная
проверка пакета на Windows не доказывает запуск на Mac.

Первый запуск большого JAR может быть медленным на Windows. Менеджер ждёт до
180 секунд и использует тот же бюджет ожидания startup.lock для параллельных
клиентов; в шаблоне Codex startup_timeout_sec = 240. Порт 17433 и схема единого
демона не меняются. Последующие чаты подключаются к уже работающему процессу.
